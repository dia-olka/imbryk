# Gazette

The Gazette is an [Eleventy](https://www.11ty.dev/) static site that renders AI-generated newspapers from the Imbryk world-building engine.


## Data flow

```
R2 (production)                     Local fixture (development)
       │                                        │
       ▼                                        ▼
editions/index.json              src/_data/fixtures/sample-edition.json
       │                                        │
  editions/{date}/{id}.json                     │
  { edition_id, date,                           │
    articles: {                                 │
      "sovereign": "<json-str>",                │
      "curator": "<json-str>"                   │
    }                                           │
  }                                             │
       │                                        │
       ▼                                        │
  Zod validation (R2IndexEntrySchema,           │
  R2EditionSchema, R2NewspaperContentSchema)    │
       │                                        │
       ▼                                        ▼
  transformR2Edition()              Zod validation (EditionSchema)
       │                                        │
       └─────────────────┬──────────────────────┘
                         ▼
              Gazette template shape:
              { edition_id, date, newspapers: [...], curator_synthesis }
                         │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
       articlePages  newspaperPages  editions
       (Zod filters (Zod filters     (template
        per article)  per article)    data)
              │
              ▼
       slugify(article.headline)   ← safe: invalid articles filtered out first
```

## Validation and error handling

All data loaded from R2 or the local fixture is validated with [Zod](https://zod.dev/) schemas defined in `src/_data/lib/schemas.ts`.

### What happens on validation failure

| Failure | Action |
|---|---|
| Invalid R2 index entry | Entry skipped; remaining editions load normally |
| Failed R2 fetch (non-2xx) | Edition skipped; build continues |
| Invalid R2 edition shape | Edition skipped |
| Newspaper with invalid articles | Edition included; invalid articles skipped downstream |
| Article missing `headline` or `body` | Article skipped in `articlePages`/`newspaperPages` before `slugify` is called |
| Invalid local fixture | Build fails immediately with a clear error message |

In every failure case, a detailed warning is logged to the console **and**, if `SENTRY_DSN` is set, sent to Sentry. Every Sentry event includes:

- **`sourceUrl`** — the full R2 URL (e.g. `https://r2.example.com/editions/2026-03-01/yz-d2-001.json`) or local file path, so operators can fetch and inspect the offending file directly.
- **`label`** — a human-readable description of what failed.
- **`zodErrors`** — the structured Zod error with field-level details.
- **`offendingData`** — the raw data that did not pass validation.

### Utility modules

| File | Purpose |
|---|---|
| `src/_data/lib/schemas.ts` | Zod schemas for R2 raw shapes and gazette template shapes |
| `src/_data/lib/sentry.ts` | `captureValidationError` and `captureLoadError` helpers |
| `src/_data/lib/loadEditions.js` | Data pipeline — fetches, validates, transforms |

## Local development

By default the build uses `src/_data/fixtures/sample-edition.json`. No additional configuration is required.

```sh
# Install dependencies
npm install

# Serve locally with live reload
pnpm nx serve gazette
```

## Running with R2 data

Set `R2_PUBLIC_URL` to point at the public R2 bucket:

```sh
R2_PUBLIC_URL=https://your-r2-bucket.example.com pnpm nx build gazette
```

## Environment variables

Copy `.env.example` to `.env` and fill in the values:

| Variable | Required | Description |
|---|---|---|
| `GAZETTE_URL` | Yes (prod) | Public URL of the Gazette site |
| `IMBRYK_APP_URL` | Yes (prod) | Public URL of the Imbryk submission app |
| `R2_PUBLIC_URL` | Prod only | Base URL of R2 edition storage; omit for local fixture |
| `SENTRY_DSN` | Optional | Sentry DSN for build-time error reporting |

## Testing

```sh
pnpm nx test gazette
```

Tests cover valid and invalid data cases for schemas and the transformation pipeline. See `src/_data/lib/loadEditions.spec.js`.

## Backend / frontend schema alignment

The backend (`apps/newsroom-director`) writes editions to R2 in this shape:

```json
{
  "edition_id": "...",
  "date": "YYYY-MM-DD",
  "articles": {
    "sovereign": "<json-string>",
    "curator": "<json-string>"
  }
}
```

Each per-newspaper JSON string is generated by Gemini and validated against `R2NewspaperContentSchema` on load. The primary risk is the LLM omitting required fields (`headline`, `body`). Invalid articles are skipped rather than crashing the build, and the omission is surfaced via Sentry with the full R2 URL.

**Recommended follow-up:** add Pydantic validation of Gemini output in `apps/newsroom-director` before writing to R2, to catch schema violations at source.
